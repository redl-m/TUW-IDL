# Speech Emotion Recognition (SER) with Wav2Vec 2.0

This project implements a Speech Emotion Recognition (SER) system using the **RAVDESS** dataset and **Wav2Vec 2.0**. It leverages End-to-End Deep Learning to classify speech into 8 emotional categories (neutral, calm, happy, sad, angry, fearful, disgust, surprised) directly from raw audio waveforms.

This is a university project created by **Alexander**, **Michi**, and **Pollyana**.

## Project Overview

* **Model:** Fine-tuned `facebook/wav2vec2-large-xlsr-53` with a custom classification head.
* **Architecture:** End-to-End Transformer-based architecture (no manual feature engineering required).
* **Augmentation:** Real-time GPU-accelerated audio augmentation (Noise, Pitch Shift, Gain) using `torch-audiomentations`.
* **Dataset:** RAVDESS (Ryerson Audio-Visual Database of Emotional Speech and Song).

## Project Structure

```text
├── data/
│   ├── raw/           # Place original RAVDESS .wav files here
│   └── processed/     # Preprocessed .pt tensors (generated by preprocess.py)
├── models/            # Saved checkpoints and best model
├── results/           # Confusion matrices and evaluation logs
├── src/
│   ├── preprocess.py  # Converts raw audio to standardized tensors
│   ├── datasets.py    # Custom Dataset class with on-the-fly augmentation
│   ├── model.py       # Wav2Vec 2.0 model definition
│   ├── train.py       # Training loop using Hugging Face Trainer
│   ├── evaluate.py    # Generates metrics and confusion matrices
│   └── train_baseline.py # MFCC + Random Forest baseline for comparison
├── Dockerfile         # Docker environment configuration
├── requirements.txt   # Python dependencies
└── README.md          # Project documentation
```

## Setup & Installation

### Option 1: Using Docker

We provide a Docker container to ensure a reproducible environment with GPU support.

1. Build the Image:
    ```bash
   docker build -t dl-dev .
   ```
2. Run the container: this command mounts important directories so changes persist.
    In addition, also the src directory gets mounted, such that the docker container 
    must not be restarted for every change.
    ```bash
    docker run --gpus all -it \
      -v "$(pwd)/results:/workspace/results" \
      -v "$(pwd)/src:/workspace/src" \
      -v "$(pwd)/data:/workspace/data" \
      -v "$(pwd)/models:/workspace/models" \
      dl-dev
    ```
    
    Instead of manually inserting this command, you can also use the docker compose file
    to build and start the container. It is also quite nice for running commands without
    needing to connect to the container manually:

    ```bash
    docker compose run python python src/script.py
    ```
   
NOTE: The gpu support only works on linux if `nvidia-container-toolkit` is installed.
Follow this [doc](https://docs.docker.com/engine/containers/resource_constraints/#gpu) for
further information. For Windows take a look at the [docs](https://docs.docker.com/desktop/features/gpu/).

### Option 2: Local installation

If you prefer running the installation globally on your device you can install the
dependencies with:

```bash
pip install -r requirements.txt
```

## Usage

We structured different parts of our project into different files. Therefore, to evaluate
the model the following files have to be executed in this order:

1. `src/preprocess.py`
2. `src/train.py`
3. `src/evaluate.py`

This can be done either by running each command on its own:

```bash
docker compose run --rm python python3 src/script.py
```

or by starting a new bash session inside the docker container:

```bash
docker compose run --rm --entrypoint bash python
```

## MISC

### NIXOS

A `shell.nix` file is also available, though only recommended for experienced users 
with nix/linux. Furthermore, the usual `python` service in `docker-compose.yml` will 
not work. Thus, use `python-nx`. For further information take a look at
[source](https://discourse.nixos.org/t/nvidia-docker-container-runtime-doesnt-detect-my-gpu/51336/15).
